НАЙДЕНА ПРИЧИНА ПАДЕНИЯ vk_* (проанализировано по core):
- Wrapper в tryLinuxVulkanCall делает: push rdi; push rsi; push r12 (3x8=24 байта), затем FF15-call.
- Если на входе в wrapper rsp % 16 == 0, то после 24 байт rsp % 16 == 8 -> call-сайт НЕ выровнен.
- Калли (реальная libvulkan vkEnumerateInstanceVersion) начинает с 6 push + sub 0x78,
  и делает movaps %xmm0,0x20(%rsp) (ELF rva 0x34DFB). При невыровненном входе rsp у movaps
  % 16 == 8 -> исключение #GP -> SIGSEGV. (Регистры core ровно это подтверждают:
  rip=libvulkan+0x34dfb, rdi=0 из xor edi,rdi в прологе, rax=rsp+0x20.)
- Отсюда же пустой stdout: print("string") в codegen пишет write(1, rsi=LEN, rdx=LEN)
  вместо rsi=адрес строки (rcx считал strlen, rax держал указатель) -> EFAULT. Это МЕЛКИЙ
  отдельный баг для печати строк (int-вывод работает). Починить, чтобы видеть вывод.
