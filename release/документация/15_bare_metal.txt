# Bare-Metal и BIOS режим

Zenith поддерживает bare-metal и BIOS режимы для создания своих операционных
систем.

## Режимы

```zenith
app bare              # плоский бинарник .bin, kernel_mode: independent (по умолчанию)
app bios              # плоский бинарник .bin (32-бит, загружается по 0x100000), kernel_mode: dependent (по умолчанию)
kernel_mode: independent   # или dependent
```

| kernel_mode | Значение |
|-------------|----------|
| `dependent` | Ядро работает «поверх» прошивки — доступны `efi_*` и `bios_*`, `int()` |
| `independent` | Ядро само владеет аппаратурой. `efi_*`/`bios_*` **запрещены** (ошибка). Для клавиатуры — `kb_hit()`/`kb_get()` (PS/2, без BIOS), для экрана — `vga_*`/`gop_*`/`fb_*` |

`app bare` по умолчанию ставит `independent` (плоский бинарник запускается
загрузчиком напрямую — прошивка уже не помогает). `app bios` по умолчанию
ставит `dependent` (BIOS-блоки на 16-битных прерываниях живут только под BIOS).
Указать `kernel_mode` явно можно в любой момент строкой атрибута.

## Сборка

```bash
zenith kernel.z          # bare -> kernel.bin (raw binary)
zenith kernel.z -o os    # bare -> os.bin
```

- `app bare`: выход — **плоский бинарный файл** (только код и данные, без
  PE-заголовка). Точка входа вызывает `main()` (или первую функцию), затем
  выполняется `hlt; jmp $`.
- `app bios`: выход — **плоский 32-бит бинарник** (без PE-заголовка),
  рассчитан на загрузку по адресу **0x100000** (загрузчик вроде `buildBiosStub`
  или собственный). Строки и глобалы адресуются абсолютно (база 0x100000).
  Точка входа вызывает `main()` (или первую функцию), затем `hlt; jmp $`.
  В коде доступны BIOS builtin-функции.

## PS/2 клавиатура (независимо от прошивки)

Доступны в обоих режимах (`independent` и `dependent`), опрашивают контроллер 8042
напрямую через порты 0x64/0x60 — прерываний BIOS не требуют:

| Функция | Описание |
|---------|----------|
| `kb_hit()` | 1, если в буфере контроллера есть данные (статус бит 0), иначе 0 |
| `kb_get()` | Блокирующий приём одного скан-кода (raw, лэй-код set 1) |

Скан-коды — «set 1» (PC/AT make-коды): `a` = 0x1E, Enter = 0x1C, Space = 0x39.
Перевод в символ — на стороне программы (раскладка свободная).

## TSC и временные задержки

| Функция | Описание |
|---------|----------|
| `rdtsc()` | 64-битный Time-Stamp Counter (число тактов с включения, удобно для тайминга) |
| `io_delay()` | Задержка записи в порт 0x80 (классическая «post»-задержка контроллеров) |

Доступны в обоих режимах, прошивка не нужна.

## VGA функции (текстовый режим 80x25)

Работают напрямую с VGA-текстовой памятью по адресу `0xB8000`
(2000 ячеек: 80 колонок × 25 строк, 2 байта на ячейку — символ + атрибут).

| Функция | Описание |
|---------|----------|
| `vga_clear()` | Залить экран пробелами (0x0720: светло-серый на чёрном), сбросить курсор |
| `vga_putc(char, attr)` | Записать символ с атрибутом на позицию курсора, курсор++ |
| `vga_print("text")` | Вывести ASCII-строку (атрибут 0x07), курсор++ |

### Курсор VGA

Позиция курсора (число ячеек от начала) хранится по адресу `0x7E00`.

### Атрибуты VGA

Байт атрибута: младшие 4 бита — цвет текста, старшие 4 бита — фон.

| Атрибут | Описание |
|---------|----------|
| 0x07 | Светло-серый на чёрном |
| 0x1F | Белый на синем |
| 0x2E | Зелёный на чёрном |
| 0x4F | Красный на чёрном |

## BIOS функции

Вызывают прерывания BIOS из 16-битного кода:

| Функция | INT | Описание |
|---------|-----|----------|
| `bios_get_char()` | 0x16 AH=0 | Блокирующий ввод: возвращает ASCII в AL (скан-код в AH) |
| `bios_check_key()` | 0x16 AH=1 | Проверить, нажата ли клавиша |
| `bios_set_cursor(x, y)` | 0x10 AH=2 | Установить курсор (страница 0) |
| `bios_scroll(lines)` | 0x10 AH=6 | Прокрутить экран вверх |
| `bios_video_mode(mode)` | 0x10 AH=0 | Установить видео-режим (3 = 80×25 текст) |
| `bios_video_int(ah)` | 0x10 | INT 0x10 с AH = младший байт аргумента |
| `bios_disk_read(drive, sector, count, buffer)` | 0x13 AH=0x42 | Чтение секторов через DAP (пакет на стеке): возвращает 0 при успехе, −1 при ошибке |
| `bios_memory_map()` | 0x15 EAX=0xE820 | Заполняет таблицу памяти в 0x7E10 (максимум 32 записи по 24 байта): возвращает число записей |

> `bios_memory_map` использует буфер по адресу 0x7E10 (24 байта на запись,
> 32 записи максимум), как и другие области ядра (курсор VGA — 0x7E00,
> параметры фреймбуфера — 0x8000..0x8018).

## Функции фреймбуфера (GOP/LFB)

`gop_*` и `fb_*` доступны и в bare-режиме: они читают параметры фреймбуфера
из фиксированных адресов, которые должен заполнить загрузчик.

| Функция | Описание |
|---------|----------|
| `gop_init()` | Проверить наличие фреймбуфера (1/0) |
| `gop_clear(color)` | Залить весь экран цветом `0x00RRGGBB` |
| `gop_pixel(x, y, color)` | Нарисовать пиксель |
| `gop_rect(x, y, w, h, color)` | Нарисовать заполненный прямоугольник |
| `gop_char(x, y, ch, fg, bg)` | Залить блок 8×16 цветом `fg` (глиф упрощён) |
| `gop_print(x, y, str, fg, bg)` | Вывести UTF-8 строку шрифтом 8×16 (кириллица) |
| `fb_clear(color)` | Залить весь фреймбуфер цветом (параметры из области 0x8000) |
| `fb_pixel(x, y, color)` | Нарисовать пиксель (адрес 0x8000, pitch 0x8008) |
| `fb_addr()` | Адрес фреймбуфера |
| `fb_width()` / `fb_height()` | Ширина / высота (пиксели) |
| `fb_pitch()` | Байт на строку |
| `fb_bpp()` | Бит на пиксель |

## Информация о фреймбуфере (bare)

Параметры фреймбуфера загрузчик записывает по фиксированным адресам:

| Адрес | Размер | Описание |
|-------|--------|---------|
| 0x8000 | 8 байт | Адрес фреймбуфера |
| 0x8008 | 4 байта | Pitch (байт на строку) |
| 0x800C | 4 байта | Ширина (пиксели) |
| 0x8010 | 4 байта | Высота (пиксели) |
| 0x8014 | 4 байта | Бит на пиксель |
| 0x8018 | 4 байта | Формат пикселя |

## Системные функции

| Функция | Описание |
|---------|----------|
| `halt()` | `cli`; бесконечный цикл `hlt` |
| `hlt()` | Остановить CPU один раз |
| `cli()` / `sti()` | Запретить / разрешить прерывания |
| `int(n)` | Программное прерывание (константа 0..255) |
| `inb(port)` / `inw(port)` / `ind(port)` | Чтение 1/2/4 байт из порта |
| `outb(port, val)` / `outw(port, val)` / `outd(port, val)` | Запись 1/2/4 байт в порт |
| `lidt(ptr)` | Загрузить IDT из памяти по адресу |
| `lgdt(ptr)` | Загрузить GDT из памяти по адресу |
| `peek(addr)` / `poke(addr, val)` | Чтение/запись 8 байт |
| `peek8` / `peek16` / `peek32` | Чтение 1/2/4 байт |
| `poke8` / `poke16` / `poke32` | Запись младших 1/2/4 байт |

## Тип phys ptr

Квалификатор `phys` доступен в EFI/bare — декларативный
маркер «физического» указателя, на кодогенерацию не влияет:

```zenith
var vga: phys ptr<int> = 0xB8000
*vga = 0x1F48          # 'H', белый на синем
*(vga + 1) = 0x1F69    # 'i'
```

## asm-блоки

`asm { ... }` доступен в bare-режиме (см. файл 14_ассемблер.txt):

```zenith
asm {
    cli
    lgdt [rax]
    mov rax, cr0
    or rax, 0x80000000
    mov cr0, rax
}
```

## Пример: bare с VGA

```zenith
app bare

func main() -> int
    vga_clear()
    vga_print("ZENITH OS v1.0")
    vga_print("Bare metal kernel")
    halt()
    return 0
end
```

## Пример: bare с GDT

```zenith
app bare

func main() -> int
    vga_clear()
    vga_print("Setting up GDT...")

    var gdt_ptr: int = 0x9000
    poke(gdt_ptr, 0x001F)
    poke(gdt_ptr + 2, 0x1000)

    lgdt(gdt_ptr)

    vga_print("Done!")
    halt()
    return 0
end
```

## Пример: bare с фреймбуфером

```zenith
app bare

func main() -> int
    if gop_init() == 0
        halt()
    end
    gop_clear(0x001F4060)
    gop_pixel(100, 100, 0x00FF0000)
    gop_rect(10, 10, 50, 50, 0x0000FF00)
    halt()
    return 0
end
```

## Пример: bios

```zenith
app bios

func main() -> int
    bios_video_mode(3)      # 80x25 текстовый режим
    var c: int = bios_get_char()
    return 0
end
```

## Формула цвета

```text
0x00RRGGBB
```

- `0x00FF0000` = Красный
- `0x0000FF00` = Зелёный
- `0x000000FF` = Синий
- `0x00FFFF00` = Жёлтый
- `0x001F4060` = Тёмно-синий
