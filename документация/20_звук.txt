# Звук — PCM-генерация и воспроизведение (sound_*, Windows)

Настоящий PCM-звук: генерация волн 8/16/24 бит, сведение дорожек
(sound_mix) и воспроизведение через **winmm.dll** waveOut. Доступны для
`app console` и `app gui` под Windows. Для `app efi` / `app bios` /
`app bare` / `app stm32` / `app arm64` эти функции недоступны.

Та же механика, что у `net_*` (импорт DLL в PE + позиционно-независимый
хелпер в .text), поэтому дополнительных файлов не требуется.

## Генерация PCM

| Функция | Что делает | Возврат |
|---------|-----------|---------|
| `sound_gen(buf, samples, rate, bits, wave, freq, vol)` | Заполняет buf PCM-сэмплами | всегда `0` |
| `sound_mix(target, src, samples)` | Сводит src в target (int16 clipping) | всегда `0` |

### Параметры `sound_gen`

| Параметр | Значения | Описание |
|----------|----------|----------|
| `buf` | указатель | Буфер для сэмплов (через `alloc()`) |
| `samples` | целое > 0 | Количество сэмплов |
| `rate` | 8000..192000 | Частота дискретизации |
| `bits` | 8, 16, 24 | Разрядность |
| `wave` | 0..4 | Форма волны (см. ниже) |
| `freq` | 0..100000 | Частота тона (`0` = тишина) |
| `vol` | 0..100 | Громкость в процентах |

### Формы волн (wave)

| Значение | Волна | Формула |
|----------|-------|---------|
| 0 | Синус | 512-точечная LUT, LUT[i] = 32767*sin(2πi/512) |
| 1 | Квадрат | +32767 если index<256, иначе −32767 |
| 2 | Треугольник | Линейный +32768..−32512..+32768 (512 точек) |
| 3 | Пила | Линейный +32768..−32640 (512 точек) |
| 4 | Шум | LCG: seed*1103515245+12345, sample = 32767−(seed>>16) |

### Параметры `sound_mix`

| Параметр | Описание |
|----------|----------|
| `target` | Буфер int16 (результат: target += src) |
| `src` | Буфер int16 (складывается в target) |
| `samples` | Количество int16-сэмплов |

Клиппинг: результат обрезается до `[−32768, +32767]`.

## Воспроизведение (waveOut)

| Функция | Что делает | Возврат |
|---------|-----------|---------|
| `sound_open(rate, bits, channels)` | Открывает waveOut-устройство | handle или `−1` |
| `sound_play(handle, buf, samples)` | Ставит буфер в очередь (async) | `0`=ок, `−1`=ошибка, `−2`=занято |
| `sound_busy(handle)` | Проверяет, играет ли буфер | `1`=играет, `0`=свободен |
| `sound_wait(handle)` | Блокируется до конца воспроизведения | `0` |
| `sound_stop(handle)` | Сброс waveOut (drop pending) | `0` |
| `sound_close(handle)` | Сброс + отключение + закрытие | `0` |

## Ограничения

- `bits` только 8, 16, 24 (не 32).
- `channels` в `sound_open` пока только 1 (mono). Стерео потребует
  расширения WAVEFORMATEX и звука с двумя каналами в `sound_gen`.
- `sound_wait` блокирующий (while busy + Sleep(1)). Для GUI-цикла
  лучше использовать `sound_busy` в своих циклах обработки сообщений.
- `sound_play` принимает один буфер. Для непрерывного воспроизведения
  нужно чередовать: `sound_wait` → заполнить новый → `sound_play`.
- Под wine (Linux) waveOutOpen может вернуть handle, но WHDR_DONE
  никогда не устанавливается (нет аудио-бэкенда).

## Пример: синтез и воспроизведение тона

```zenith
app console

func main() -> int
    var buf: int = alloc(88200)   # 44100 сэмплов × 2 байта

    # 440 Hz синус, 44100 Hz, 16 бит, полная громкость
    sound_gen(buf, 44100, 44100, 16, 0, 440, 100)

    var h: int = sound_open(44100, 16, 1)
    if h >= 0
        sound_play(h, buf, 44100)
        sound_wait(h)
        sound_close(h)
    end

    return 0
end
```

## Пример: двухголосный микс (реальные дорожки)

```zenith
app console

func main() -> int
    var voice: int = alloc(176400)   # 44100 × 2 байта
    var drums: int = alloc(176400)
    var mix:   int = alloc(176400)

    # Мелодия: 523 Hz (до5), 16 бит, 70%
    sound_gen(voice, 44100, 44100, 16, 0, 523, 70)

    # Ритм: шум, 44100 Hz, 16 бит, 40%
    sound_gen(drums, 44100, 44100, 16, 4, 0, 40)

    # Сведение: mix = voice + drums с клиппингом
    sound_mix(mix, voice, 44100)
    sound_mix(mix, drums, 44100)

    var h: int = sound_open(44100, 16, 1)
    if h >= 0
        sound_play(h, mix, 44100)
        sound_wait(h)
        sound_close(h)
    end

    return 0
end
```

## Пример: арпеджио 8-бит

```zenith
app console

func main() -> int
    var buf: int = alloc(8820)
    var h: int = sound_open(22050, 8, 1)
    if h < 0
        return 1
    end

    # Ноты до4-ми-соль-до5 (арпеджио 44100 сэмплов на ноту)
    var notes: [4]int
    notes[0] = 262
    notes[1] = 330
    notes[2] = 392
    notes[3] = 523

    var i: int = 0
    while i < 4
        sound_gen(buf, 2205, 22050, 8, 2, notes[i], 80)
        sound_play(h, buf, 2205)
        sound_wait(h)
        i = i + 1
    end

    sound_close(h)
    return 0
end
```

## Как это работает внутри

- Компилятор при использовании `sound_*` добавляет `winmm.dll` в таблицу
  импорта PE (6 функций: waveOutOpen, waveOutPrepareHeader, waveOutWrite,
  waveOutUnprepareHeader, waveOutReset, waveOutClose).
- `sound_gen` и `sound_mix` вызывают один позиционно-независимый хелпер
  в .text (7 массивов волн × 3 битовых региона = 15 самодостаточных циклов)
  через `call rel32`. Хелпер не трогает callee-saved регистры и
  возвращает `0` в `rax`.
- ЛУТ синуса (512×int16 = 1024 байта) генерируется компилятором через
  `std::sin` и размещается в .data.
- `sound_open/play/...` — прямые вызовы winmm.dll через import thunk,
  callee-saved регистры (rdi/rsi/r12) сохраняются по шаблону `net_*`.
- Регистры r8/r9/r10 используются как аргументы (wave/freq/vol) и
  step/phase аккумулятор — не входят в пул аллокатора, не конфликтуют
  с основной кодогенерацией.
