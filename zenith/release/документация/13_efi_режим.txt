# UEFI / EFI режим

Zenith компилирует UEFI-приложения (PE32+ EFI).
Используйте `app efi`.

## Включение

```zenith
app efi

func main() -> int
    gop_clear(0x001F4060)
    gop_print(10, 10, "Hello UEFI!", 0x00FFFFFF, 0x001F4060)
    halt()
    return 0
end
```

## kernel_mode

```zenith
app efi
kernel_mode: dependent   # по умолчанию для efi/bios
```

Управляет доступом к функциям BIOS/UEFI и правилам генерации кода:

| Режим | Значение | Доступные builtin |
|-------|----------|-------------------|
| `dependent` (по умолчанию для `app efi` / `app bios`) | Ядро работает «поверх» прошивки: можно вызывать `efi_*`, `bios_*`, ConIn/ConOut, VGA BIOS | Всеbuiltin-функции: EFI, GOP, клавиатура и т.д. |
| `independent` (по умолчанию для `app bare`) | Ядро само владеет аппаратурой, прошивка не используется | Запрещены `efi_*` и `bios_*` (ошибка компиляции). Доступны прямые функции: `kb_hit`/`kb_get`, `vga_*`/`gop_*`/`fb_*`, `inb`/`outb`, `peek`/`poke`, `asm { }` |

В `independent` вызов `efi_get_char()`/`bios_get_char()` выдаёт ошибку с
подсказкой (используйте `kb_hit()`/`kb_get()` для PS/2 или `int()` для
программных прерываний). `dependent` разрешает фирмварь-функции — но тогда
ядро не может менять режимы CPU/GDT/IDT критично.

## Сборка

```bash
zenith boot.z               # -> BOOTX64.EFI
zenith boot.z -o myos.efi  # -> myos.efi
```

Выход — PE32+ EFI-образ: запускается прошивкой через `EfiMain`.
Точка входа передаёт `ImageHandle` и `SystemTable` во внутренние глобалы
(win32Globals+0 и +8), ищет протокол `EFI_GRAPHICS_OUTPUT_PROTOCOL`,
активирует текущий режим (`SetMode`) и кэширует параметры фреймбуфера в
win32Globals+24..48, после чего вызывает `main()`.

## GOP функции (Graphics Output Protocol)

Пиксельные/текстовые функции рисуют напрямую в линейный фреймбуфер.
Цвет — `0x00RRGGBB` (в памяти BGRA, 8 бит на канал).

| Функция | Описание |
|---------|----------|
| `gop_init()` | Проверить доступность GOP (1 — есть, 0 — нет) |
| `gop_clear(color)` | Залить весь экран цветом |
| `gop_pixel(x, y, color)` | Нарисовать пиксель |
| `gop_rect(x, y, w, h, color)` | Нарисовать заполненный прямоугольник |
| `gop_char(x, y, ch, fg, bg)` | Залить блок 8×16 цветом `fg` (упрощённый глиф: сам символ игнорируется, рисуется сплошной блок) |
| `gop_print(x, y, str, fg, bg)` | Вывести UTF-8 строку встроенным шрифтом 8×16 (см. ниже) |
| `gop_print_hex(x, y, val, fg, bg)` | Вывести 64-битное число `val` как 16 шестнадцатеричных цифр (0–F, встроенный шрифт 8×16) |

`gop_print` поддерживает:
- ASCII 32..126;
- кириллицу: А–Я, а–п, р–я, а также Ё и ё;
- неизвестные/неполные байты пропускаются (символ не выводится);
- каждый символ занимает 8 пикселей по горизонтали, 16 по вертикали;
- позиция `x, y` — верхний левый угол первой буквы (в пикселях).

## Функции фреймбуфера

| Функция | Описание |
|---------|----------|
| `fb_addr()` | Адрес фреймбуфера (64-бит) |
| `fb_pitch()` | Байт на строку |
| `fb_width()` | Ширина экрана (пиксели) |
| `fb_height()` | Высота экрана (пиксели) |
| `fb_bpp()` | Бит на пиксель (32 для форматов 0/1) |

В EFI-режиме эти значения кэшируются точкой входа из GOP
(win32Globals+24..48) и читаются инструкцией `mov [rip+disp]`.
До инициализации (или если GOP не найден) они равны 0.

## Формула цвета

```text
0x00RRGGBB
```

- `0x00FF0000` = Красный
- `0x0000FF00` = Зелёный
- `0x000000FF` = Синий
- `0x00FFFF00` = Жёлтый
- `0x00FFFFFF` = Белый
- `0x001F4060` = Тёмно-синий

## EFI System Table функции

| Функция | Описание |
|---------|----------|
| `efi_image_handle()` | Вернуть EFI_HANDLE (ImageHandle точки входа) |
| `efi_system_table()` | Вернуть EFI_SYSTEM_TABLE* |
| `efi_print("text")` | Печать через ConOut->OutputString (UTF-8 конвертируется в UCS-2, до 255 символов) |
| `efi_exit(status)` | Вернуть статус из EfiMain (status в eax) |

## Ввод с клавиатуры

Ввод идёт через `ConIn->ReadKeyStroke` (протокол
`EFI_SIMPLE_TEXT_INPUT_PROTOCOL`). ReadKeyStroke **потребляет** клавишу,
поэтому неблокирующий опрос кэширует её во внутренних глобалах (флаг +52,
scan-код +53, unicode +54).

| Функция | Описание |
|---------|----------|
| `efi_get_char()` | Блокирующая. Возвращает UnicodeChar (нижний байт). Для спец-клавиш (стрелки, F-клавиши) UnicodeChar = 0 — используйте `efi_get_key()` |
| `efi_check_key()` | Неблокирующая. Возвращает 1, если клавиша доступна (кэширует её), иначе 0. Клавиша не теряется |
| `efi_get_key()` | Блокирующая. Возвращает 32-бит код: `(ScanCode << 16) \| UnicodeChar` |

Scan codes спец-клавиш (верхние 16 бит `efi_get_key`):

| Клавиша | ScanCode |
|---------|----------|
| Up | 0x0001 |
| Down | 0x0002 |
| Right | 0x0003 |
| Left | 0x0004 |
| Home | 0x0005 |
| End | 0x0006 |
| Insert | 0x0007 |
| Delete | 0x0008 |
| PageUp | 0x0009 |
| PageDown | 0x000A |
| F1..F10 | 0x000B..0x0014 |
| Escape | 0x0017 |

Пример опроса клавиатуры без блокировки:

```zenith
app efi

func main() -> int
    efi_print("Press any key...")
    while efi_check_key() == 0
        # ждём клавишу, не блокируя CPU
    end
    var k: int = efi_get_char()   # вернёт закэшированную клавишу
    halt()
    return 0
end
```

## Системные функции (EFI/bare)

| Функция | Описание |
|---------|----------|
| `halt()` | `cli`; бесконечный цикл `hlt` |
| `hlt()` | Остановить CPU один раз |
| `cli()` | Запретить прерывания |
| `sti()` | Разрешить прерывания |
| `int(n)` / `interrupt(n)` | Программное прерывание (n — константа 0..255; `interrupt` — синоним) |
| `rdtsc()` | 64-битный Time-Stamp Counter (тайминг без прошивки) |
| `io_delay()` | Задержка записи в порт 0x80 |
| `inb(port)` / `inw(port)` / `ind(port)` | Чтение 1/2/4 байт из порта |
| `outb(port, val)` / `outw(port, val)` / `outd(port, val)` | Запись 1/2/4 байт в порт |
| `lidt(ptr)` | Загрузить IDT из памяти по адресу |
| `lgdt(ptr)` | Загрузить GDT из памяти по адресу |
| `peek(addr)` / `poke(addr, val)` | Чтение/запись 8 байт |
| `peek8` / `peek16` / `peek32` | Чтение 1/2/4 байт (с нулевым расширением) |
| `poke8` / `poke16` / `poke32` | Запись младших 1/2/4 байт |

VGA-функции (`vga_clear`, `vga_putc`, `vga_print`) тоже доступны в EFI-режиме
(см. файл 15_bare_metal.txt), но в UEFI без VGA-режима писать в 0xB8000
обычно бессмысленно — используйте GOP.

## Тип phys ptr

Квалификатор `phys` доступен в EFI/bare и является
объявлением «физического» указателя:

```zenith
var fb: phys ptr<int> = fb_addr()
var p: int = fb[0]      # чтение int через физический адрес
```

Это чисто декларативный маркер: парсер принимает и хранит его, но на
кодогенерацию он не влияет.

## Ограничения

- Нет `print()`, `sleep()`, `pause()` и GUI-функций (только Windows/EFI).
- Нет DX11 и аллокаторов кучи (куча есть в PE-режимах; в EFI/bare
  зарезервировано 64 MB в `.bss`, см. 08_память.txt).
- Неподдерживаемая инструкция в asm-блоке: warning и пропуск.

## Пример: UEFI с GOP

```zenith
app efi

func main() -> int
    if gop_init() == 0
        halt()
    end

    var w: int = fb_width()
    var h: int = fb_height()

    gop_clear(0x001F4060)
    gop_rect(10, 10, 100, 50, 0x00FF0000)
    gop_rect(120, 10, 100, 50, 0x0000FF00)
    gop_print(10, 80, "Zenith OS", 0x00FFFFFF, 0x001F4060)

    halt()
    return 0
end
```

## Пример: EFI с ConOut

```zenith
app efi

```
