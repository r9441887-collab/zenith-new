# Язык Зенит — Краткий обзор

**Zenith** — компилируемый язык программирования для разработки игр,
системного ПО, UEFI-загрузчиков и bare-metal ядер.
Компилируется напрямую в x86_64 машинный код без внешних зависимостей
(нет runtime, нет libc). Выходные форматы: `.exe` (PE), `.efi` (PE32+ UEFI),
`.bin` (плоский бинарник).

## Быстрый старт

```zenith
app console

func main() -> int
    print("Привет, мир!")
    return 0
end
```

## Типы приложений

Каждый файл `.z` обязан начинаться с директивы `app`:

| Директива | Описание | Выход |
|-----------|----------|-------|
| `app console` | Консольное приложение (print, alloc, sleep, peek/poke, http_get) | `.exe` |
| `app gui` | GUI-приложение (окна, рисование, ввод). **Обязательно** указать категорию `tool` или `game` | `.exe` |
| `app efi` | UEFI-приложение (.efi, BOOTX64.EFI) | `.efi` |
| `app bios` | Режим с вызовом BIOS-прерываний (INT 0x10, 0x16) | `.bin` (плоский 32-бит, база 0x100000) |
| `app bare` | Bare-metal, плоский бинарный образ | `.bin` |
| `app stm32` | Микроконтроллеры STM32 (ARM Cortex-M, Thumb/Thumb-2), см. 16_stm32.txt | `.bin` (прошивка по адресу 0x08000000) |
| `app arm64` | 64-битный ARM (AArch64, Cortex-A53+), прошивка для QEMU `virt`, см. 17_arm64.txt | `.bin` (плоский образ) |

### GUI: рендер и категория

Рендер и категория задаются ключевыми словами **в той же строке** после `app gui`
(в любом порядке). Отдельных директив `type sr` / `type dx` **не существует**.

```zenith
app gui tool          # программный рендер (по умолчанию) + категория Tool
app gui sr game       # программный рендер + категория Game
app gui dx tool       # DirectX 11 + категория Tool
app gui dx game       # DirectX 11 + категория Game
```

- `sr` / `dx` — выбор рендера (по умолчанию `sr`, software/GDI).
- `tool` / `game` — обязательная категория. От неё зависит доступ к
  функциям: `drawRect`/`drawLine`/`drawText`/`textWidth` (Tool) и
  `rand`/`getTime`/`playTone` (Game).
- Без категории компилятор выдаёт ошибку.

### kernel_mode (EFI / BIOS / bare)

Необязательная директива после `app`, управляет доступом к функциям прошивки:

```zenith
app efi
kernel_mode: independent
# или
kernel_mode: dependent
```

- `independent` — ядро само владеет аппаратурой, прошивка не используется.
  Функции прошивки (`efi_*`, `bios_*`) **запрещены** — ошибка компиляции с
  подсказкой. Вместо них доступны прямые функции: `kb_hit()`/`kb_get()`
  (клавиатура PS/2), `vga_*`/`gop_*`/`fb_*` (экран), `inb`/`outb`,
  `peek`/`poke`, `asm { }`.
- `dependent` — ядро работает «поверх» прошивки: доступны `efi_*`, `bios_*`
  и `int()`.

По умолчанию: `app bare` → `independent`; `app efi` / `app bios` → `dependent`.
Явно указать режим можно в любой момент строкой `kernel_mode: ...`.

## Структура файла

```zenith
app gui tool                # 1. Директива типа приложения (+ рендер + категория)

@import("user32.dll")       # 2. Импорт DLL

extern func MessageBoxA(h: int, text: int, caption: int, type: int) -> int   # 3. Внешние функции

struct Point                # 4. Объявление структур
    var x: float
    var y: float
end

var globalVar: int = 0      # 5. Глобальные переменные (.data)

func main() -> int          # 6. Точка входа — func main()
    # ... тело ...
    return 0
end
```

### Переменные и операторы

```zenith
var x: int = 10      # изменяемая переменная
let y: int = 20      # изменяемая (синоним var)
const MAX: int = 100 # неизменяемая: присваивание MAX = ... — ошибка компиляции
```

- `var` / `let` — изменяемые переменные; `const` — неизменяемые.
  Попытка присвоить значение `const`-переменной (включая `const`-глобальные)
  даёт ошибку компиляции `cannot assign to const variable`.
- `%` — остаток от деления (бинарный оператор, обычно с пробелами: `a % b`).
- `N% = expr` (или `N% expr`) — «N процентов от expr»: число N от 1 до 100,
  сразу за которым идёт `%` (без пробела) и выражение. Знак `=` необязателен.
  Результат — целое число `(N * expr) / 100` с округлением вниз. Работает в
  любых выражениях, но результат **обязан использоваться** (например,
  `print(50% = 20)` или `var a = 25% = 100`); голое `50% = 20` в качестве
  отдельной инструкции — ошибка компиляции.

```zenith
print(50% = 20)        # 10  (50% от 20)
var a: int = 25% 100   # 25  (знак '=' можно опустить)
if 50% = 20 > 3        # (50% от 20) > 3  → 10 > 3
    # ...
end
```

## Компиляция

```bash
# Обычная сборка
zenith examples/main.z -o game.exe

# EFI-сборка (автоматически → BOOTX64.EFI)
zenith boot.z

# С указанием имени
zenith boot.z -o myos.efi

# Bare-metal → .bin
zenith kernel.z -o kernel.bin

# Сборка загрузочного ISO-образа (ISO 9660 + El Torito)
# Только для app efi / app bare / app bios
zenith boot.z --iso          # -> BOOTX64.EFI + BOOTX64.iso
zenith boot.z -o myos.bin --iso   # -> myos.bin + myos.iso

# Проектная сборка (все .z из каталога проекта)
zenith build

# Сборка DLL (модуль без main / [no_main])
zenith --lib module.z -o module.dll
```

### Принудительная архитектура (--32bit / --64bit / --arm / --efi)

По умолчанию архитектура определяется из директивы `app`:
STM32 → ARM, BIOS → x86-32, bare+`dependent` → x86-32, EFI → x86-64,
остальное → x86-64. Принудительно её можно задать флагом:

| Флаг | Архитектура | Кому нужен |
|------|-------------|------------|
| `--32bit` | x86-32 | Обязателен для `app bios` и `app bare` + `kernel_mode: dependent` |
| `--64bit` | x86-64 | Обязателен для `app efi` |
| `--arm` | ARM (Cortex-M) | Обязателен для `app stm32` |
| `--efi` | — | Флаг совместимости (тип приложения берётся из `app efi`) |

Неверные сочетания отклоняются с ошибкой (например, `app stm32` с `--64bit`).

```bash
zenith kernel.z --32bit
zenith boot.z --64bit
zenith fw.z --arm
```

### Проекты: zenith new и workspace.zen

```bash
zenith new mygame          # создаёт mygame/ с src/main.z, workspace.zen, exe/
zenith new --lib mylib     # DLL-проект: src/main.z с меткой [no_main]
cd mygame
zenith build               # собрать проект из workspace.zen
zenith build --lib         # собрать как DLL
```

`workspace.zen` — файл проекта. Каждая строка — каталог с исходниками
(все `.z` из них компилируются вместе, порядок сортируется). Строка
`output dll` включает DLL-режим:

```text
# workspace.zen
src
output dll
```

Структура проекта: `src/` — исходники, `exe/` — выходные файлы.

### Флаги оптимизации и IR-конвейер

| Флаг | Действие |
|------|----------|
| `--no-opt` | Отключить оптимизатор (по умолчанию — максимальный) |
| `--ir` | Собрать через ассемблер-IR конвейер (IRGen → IROpt → IRAsm, только `app console`) |
| `-0r` / `-1r` / `-2r` | Уровень оптимизации по размеру для `app stm32` (нет / базовый / максимальный) |

`--ir` компилирует консольное приложение через промежуточное
представление (IR) с последующей раскраской регистров и сборкой в
x86-64 PE; для остальных типов приложений и DLL-режима конвейер
автоматически откатывается на классический бэкенд.

### Ключевые особенности

- Никаких внешних зависимостей (нет runtime, нет libc)
- Прямая генерация x86_64 машинного кода
- Windows PE формат (.exe / .dll), UEFI PE32+ (.efi), плоский бинарник (bare)
- Загрузочные ISO-образы (ISO 9660 + El Torito) через `--iso` для efi/bare/bios
- Указатели: `ptr<T>`, `virt ptr<T>`, `phys ptr<T>` (физические адреса — только EFI/bare)
- Операции с указателями: `&x` (взятие адреса), `*p` (разыменование), `*p = v` (запись)
- Неизменяемые переменные `const` и оператор процентов `N% = expr` (см. «Переменные и операторы»)
- Встроенные аллокаторы памяти: bump (`alloc`/`free`), arena, pool, slot
- 2D-графика через software rendering (GDI) или DirectX 11
- Ввод с клавиатуры: `getKey()` (GUI), `efi_get_char()`/`efi_get_key()` (EFI), `bios_get_char()` (BIOS)
- Многопоточность через libs.dll (thread, mutex, async, threadpool)
- Модульная DLL-система с `@import`, `extern ... from` и `--embed`
- Оптимизатор (удаление неиспользуемых функций и глобальных переменных)
- Multi-file проекты через `zenith build`
- Встроенный мини-ассемблер x86-64 (только EFI/bare: `asm { ... }`)
- Прерывания, порты ввода-вывода, MSR (только EFI/bare/bios)
- Таргет `app stm32` — прошивки для микроконтроллеров STM32 (GPIO, LED, задержки), см. 16_stm32.txt
- Таргет `app arm64` — прошивки для 64-битного ARM (AArch64, QEMU `virt`, UART PL011), см. 17_arm64.txt
- Сетевые функции `http_get(url)` / `http_last_error()` для Windows (WinINet), см. 18_сеть.txt
- Встроенный JS-интерпретатор `js_reset()` / `js_eval()` / `js_result()` / `js_error()` для Windows, см. 19_js.txt
