# Android (app android)

Zenith компилирует нативные 64-битные приложения для **Android 11
(`arm64-v8a`)**. Выход — статический ELF64, который Android запускает
напрямую: без `libc`, без динамического линкера, без NDK.

Программа обращается к ядру напрямую через `svc #0` (Linux-системные
вызовы AArch64). Никаких внешних тулчейнов не требуется — компилятор сам
кодирует все инструкции.

## Тип приложения

```zenith
app android
    api_level: 30      # необязательно (Android 11 = 30)
    min_sdk: 21        # необязательно (минимальный уровень устройства)
    label: myapp       # необязательно (метка)
```

| Директива | Значение | По умолчанию |
|-----------|----------|--------------|
| `api_level:` | Уровень API, под который написана программа (записывается в `.note.android.ident`) | `30` |
| `min_sdk:` | Минимальный уровень API, на котором программа разрешена запускаться | `21` |
| `label:` | Произвольная метка | пусто |

Ограничения (проверяются компилятором):

- `api_level >= 21` и `min_sdk >= 21` — именно с Android 5.0 (API 21)
  появился 64-битный `arm64-v8a`;
- `min_sdk <= api_level`;
- архитектура `arm64-v8a` выбирается автоматически, отдельная директива
  не нужна.

## Сборка и запуск

```bash
zenith app.z -o app.elf
```

Полученный файл — статический ELF. На устройстве:

```bash
adb push app.elf /data/local/tmp/app.elf
adb shell chmod 755 /data/local/tmp/app.elf
adb shell /data/local/tmp/app.elf
```

Запуск идёт от отдельного процесса (`execve`), поэтому программа
завершается сама — `main` может просто вернуть код возврата.

Точка входа — `func main()` (либо первая функция, если `main` нет).
Код возврата `main` становится кодом завершения процесса, поэтому
`return 1` действительно даст exit status 1.

## Структура ELF

| Часть | Содержимое |
|-------|------------|
| `PT_NOTE` | `.note.android.ident` с `NT_VERSION` = `r<api_level>` |
| `PT_LOAD` (R+X) | ELF-заголовки, рантайм-помощники, функции, строки |
| `PT_LOAD` (R+W) | глобальные переменные |
| `PT_GNU_STACK` | Неисполняемый стек |

Намеренно **нет** `PT_INTERP` и `PT_DYNAMIC`: Android не запускает
`/system/bin/linker64`, ядро грузит образ сам. `e_entry` указывает на
`_start`, который выставляет `sp`, читает `argc` из `[sp]` и передаёт
управление в `main`, после чего завершает процесс.

Адрес загрузки по умолчанию — `0x400000` (тот же базовый адрес линейки
`app linux`).

## Вывод текста

`print()` / `println()` пишут в файловый дескриптор `1` (stdout) через
системный вызов `write`. Перевод строки — `\n`. Числа печатаются со
знаком, целыми.

## Встроенные функции

| Функция | Описание |
|---------|----------|
| `print(x)` | Вывести строку / целое / символ в stdout |
| `println(x)` | То же, но с переводом строки |
| `alloc(size)` | Выделить память (страница + заголовок), вернуть указатель или `0` |
| `free(ptr)` | Освободить память, выделенную `alloc()` |
| `exit(code)` | Завершить процесс с кодом |
| `sleep(ms)` / `delay_ms(ms)` | Задержка через `nanosleep` |
| `delay_us(us)` | Задержка с микросекундным разрешением |
| `millis()` | Миллисекунды монотонных часов |
| `micros()` | Микросекунды монотонных часов |
| `rdtsc()` | "Счётчик тактов" — на этом таргете тоже наносекунды |
| `getpid()` | Идентификатор процесса |
| `argc()` | Число аргументов командной строки |
| `abs(x)` | Модуль числа |
| `min(a, b)` / `max(a, b)` | Минимум / максимум |
| `clamp(x, lo, hi)` | Ограничить `x` диапазоном `[lo; hi]` |
| `str_len("text")` | Длина строки в байтах |

`gpio_*` и `led_*` на этом таргете не имеют эффекта (компилятор выдаёт
предупреждение) — у обычного Android-устройства нет такого MMIO.

## Память

`alloc(size)` выделяет через `mmap(MAP_ANONYMOUS|MAP_PRIVATE)`, округляя
размер вверх до страницы. Анонимный маппинг обнулён ядром, поэтому
`alloc()` заодно заменяет `calloc()`. В первых 16 байтах блока хранится
округлённая длина — по ней `free()` понимает, сколько байт снимать, и
возвращает страницы ядру целиком. Указатель, который получает программа,
выровнен по 16 байт (максимальное естественное выравнивание AArch64).

## Модель данных

- **LP64**: глобальные переменные, локальные и параметры занимают по
  8 байт и читаются/пишутся полным 64-битным регистром. Это нужно, чтобы
  64-битный указатель из `alloc()` не обрезался, когда его кладут в
  переменную типа `int`.
- `int`, `float`, `bool` занимают 4 байта, но слоты выровнены по 8.
  **Вещественные числа не поддерживаются** (как и в `app arm64`):
  компилятор печатает диагностику («float literals are not supported yet»
  и т. п.), но **продолжает сборку** — вещественное значение при этом не
  вычисляется. Если программе нужна арифметика с дробными числами, считайте
  целые (например, тысячные доли) либо ждите появления поддержки float.
- Структуры: каждое поле выровнено по 8 байт, итоговый размер тоже
  кратен 8 (настоящий LP64-layout, а не 4-байтовый, как в `app arm64`).
- Строки — 64-битные указатели на байты в сегменте данных (тоже, как в
  других таргетах). `print()`/`println()` понимают строковый литерал или
  целое число; переменная типа `string` — это указатель, поэтому
  `print(s)` напечатает адрес, а не текст. Это общее поведение Zenith
  (см. `07_вывод_в_консоль.txt`), а не особенность Android.
- Массивы, глобальные переменные, вложенные циклы и ветвления —
  поддерживаются.
- Аргументы функций — в регистрах `x0..x7` (до 8), результат в `x0`;
  локальные переменные живут в кадре вызываемого; `sp` выровнен по
  16 байт.

## Ограничения

- Только `arm64-v8a`. 32-битные ABI (`armeabi-v7a`) не поддерживаются.
- Нет вещественных чисел, `string` как отдельного типа, файлового ввода-вывода
  и сети — но любой из этих вызовов можно добавить поверх `svc #0`.
- Смешивание с C/C++ (`--cc` / `--cxx`) пока не поддерживается: готовые
  объекты собраны под glibc, а Android использует Bionic. Компилятор
  выдаёт понятную ошибку вместо тихой поломки.
- Аргументы командной строки не копируются в доступную память, доступен
  только счётчик `argc()`.

## Пример

```zenith
app android
    api_level: 30
    min_sdk: 21

func main() -> int
    println("Zenith on Android 11")

    var buf: int = alloc(1024)
    if buf != 0
        free(buf)
        println("allocated and released")
    end

    sleep(100)
    return 0
end
```

Сборка и проверка:

```bash
zenith app.z -o app.elf
file app.elf            # ELF 64-bit LSB executable, ARM aarch64, statically linked
readelf -hlW app.elf    # нет INTERP и DYNAMIC — образ запускается сам
```

## Проверка

В репозитории лежит самопроверяющаяся программа
`tools/android_smoke.z`: она печатает `ALL PASS` и возвращает `0` только
если все утверждения выполнены (арифметика, строки, циклы, `switch`,
указатели LP64, `alloc`/`free`, сравнения, `sleep`/`delay_us`,
`micros`/`millis`, `getpid`).

```bash
zenith tools/android_smoke.z -o smoke.elf
chmod +x smoke.elf

# на устройстве:
adb push smoke.elf /data/local/tmp/smoke
adb shell chmod 755 /data/local/tmp/smoke
adb shell /data/local/tmp/smoke; echo "exit=$?"   # ожидается ALL PASS, exit=0

# без устройства — user-mode эмуляция (работает, т.к. образ статический):
qemu-aarch64-static ./smoke.elf; echo "exit=$?"
```

Ненулевой код возврата означает, что первая несошедшаяся проверка
напечатает `FAIL: ...`, и номер утверждения будет виден в выводе.
