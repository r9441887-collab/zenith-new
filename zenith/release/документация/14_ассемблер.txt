# Встроенный мини-ассемблер

Zenith включает мини-ассемблеры для прямых вставок машинного кода. Поддержка
**не ограничена** конкретными приложениями — `asm { }`, `asm32 { }`, `asm16 { }`
доступны во всех типах приложений (`app console`/`gui`/`linux`/`efi`/`bios`/
`bare`/`arm64`/`stm32`), кроме `app wasm`. Валидация ширины операндов
выполняется на этапе генерации кода и зависит от таргета (см. «Валидация
ширин» ниже). Сами блоки — x86-64 (все x86-таргеты и `asm_word_size: 16`),
AArch64 (`app arm64`) или Thumb-2 (`app stm32`).

## Матрица таргетов и ширин

| Таргет | Нативная ширина | `asm {}` | `asm32 {}` | `asm16 {}` |
|--------|-----------------|----------|------------|------------|
| `app efi` / `app bare` (x86-64) | 64 | да (64-bit) | да (32-bit) | нет (ошибка) |
| `app console` / `app gui` / `app linux` / x86-64 | 64 | да | да | нет (ошибка) |
| x86-32 (`--32bit`) | 32 | да (32-bit) | да | нет (ошибка) |
| `app bios` / `app bare` + `asm_word_size: 16` | 16 | да (16-bit) | нет (ошибка) | да |
| `app arm64` (AArch64) | 64 | да (x*/w* регистры) | да (w* регистры) | нет (ошибка) |
| `app stm32` (Thumb/Thumb-2) | 32 | да | да | нет (ошибка) |
| `app wasm` | — | нет (ошибка при разборе) | нет | нет |

Валидация — ошибка компиляции на этапе генерации кода, например:
`asm16 blocks are not supported for x86-64 target: use 'asm' (native 64-bit) and 'asm32', but not 'asm16'`.

## Синтаксис

Есть три ключевых слова: `asm { }` (нативная ширина таргета), `asm32 { }`
(32-битные операнды) и `asm16 { }` (16-битный real-mode):

```zenith
app bare

func main() -> int
    asm {
        mov rax, 42
        push rax
        pop rbx
        xor rcx, rcx
        ret
    }
    asm32 {
        mov eax, 0xB8000      # 32-битная адресация, без REX.W
        in al, 0x64           # e5 64
        out 0x80, al          # e7 80
    }
    return 0
end
```

- Каждая строка: `мнемоника операнд1[, операнд2[, операнд3]]`
- Операнды разделяются запятой
- Мнемоника регистронезависима
- Суффиксы ширины в мнемонике (`.w`/`.W`, например `add.w r9, r8, r1`)
  принимаются и игнорируются — эмиттер сам выбирает кодировку
- Поддерживаются регистровые списки `{ ... }` (Thumb `push`/`pop`) и
  индексная адресация `[база, смещение]`

> **Важно:** символ `#` в Zenith — это комментарий до конца строки, поэтому в
> ассемблерных блоках ARM/Thumb **не пишите** `#` перед операндами:
> используйте `mov r0, 5`, `add r1, r0, 3`, `[r3, 4]` вместо `#5`, `#3`, `[r3, #4]`.

`asm32` полезен для бутстрапа: драйверов, работающих с 32-битным портом I/O
(`in al, dx` / `out dx, al`), записи в legacy VGA (0xB8000) и 32-битных
значений без префикса REX.W. Все инструкции кодируются как в 32-битном
режиме процессора, поэтому регистры `e*` — настоящие 32-битные (не
усечённые версии 64-битных).

### asm16 { } — 16-битный real-mode код

Блок `asm16 { }` кодирует инструкции в 16-битном real-mode формате
(16-битные операнды и адресация, без REX/32-битных префиксов):

```zenith
app bios

func main() -> int
    asm16 {
        mov ax, 0x0F00      # режим 0x0F (80x25, 16 цветов)
        int 0x10            # вызов BIOS video interrupt
    }
    return 0
end
```

Регистры в `asm16 {}` — только 16-битные (`ax`, `cx`, `dx`, `bx`, `sp`,
`bp`, `si`, `di`); допускаются также 8-битные (`al`, `cl`, `bl`, ...).
Поддерживаются те же группы инструкций, что и в `asm32` (mov/арифметика/
логика/сдвиги/стек/переходы/`int`/`cli`/`sti`/`hlt`/порты). `int` кодируется
как `cd imm8` — его можно вызывать прямо из boot-кода.

### asm_word_size: 16 — pure 16-bit real-mode образ

Директива `asm_word_size: 16` в секции `app` переключает **весь компилятор**
на генерацию чистого 16-битного real-mode boot-образа:

```zenith
app bios
asm_word_size: 16

func add(a: int, b: int) -> int
    return a + b
end

func main() -> int
    asm16 {
        mov ax, 0x0F00
        int 0x10
    }
    var x: int = add(1, 2)
    return x
end
```

Что меняется:

- Вместо PE/EFI/Bare-образа генерируется плоский 16-битный образ
  (`.bin`), который загружается BIOS'ом напрямую (entry в начале файла,
  стек настраивается под 0x9C00, затем `call main`).
- Весь обычный код Zenith (функции, локальные переменные, `if`/`while`,
  арифметика, вызовы) эмитируется в 16-битном real-mode: пролог/эпилог
  `push bp; mov bp,sp`, локальные переменные через `[bp+disp8]`,
  значения через аккумулятор `ax`.
- Обычные `asm { }` работают — компилятор сам выбирает 16-битное кодирование
  (нативная ширина в `asm_word_size: 16`). `asm32 { }` в этом режиме
  запрещен; используйте `asm { }` или `asm16 { }`.
- Требуется `app bios` (или `app bare`). Образ загружается BIOS по адресу
  0x7C00.

## Операнды

Поддерживаются только три формы:

| Вид | Примеры |
|-----|---------|
| Регистр | `rax`, `rcx`, `r8` |
| Константа (immediate) | `42`, `0xB8000`, `-16` |
| Память `[reg]`, `[reg+N]`, `[reg-N]` | `[rax]`, `[rdx+8]`, `[rsp-32]` |

- Константы: десятичные (`42`) и hex (`0xB8000`), поддерживается минус.
- Память — только `база + смещение`. Масштабирование `[rax + rcx*4]`
  и 32-битные режимы адресации **не поддерживаются**.

## Регистры

Имена 64/32/16/8-бит принимаются все. Ширина определяется типом операнда:

- в `asm {}` 64-битные регистры кодируются с REX.W (как раньше). Если
  написать `eax`/`al`/`ax` — эмиттер по-прежнему ставит REX.W для
  совместимости (см. «Ограничения»);
- в `asm32 {}` используется только 32-битное кодирование: `eax` — это
  настоящий 32-битный регистр, REX.W не выставляется, `mov eax, 0xB8000`
  даёт `b8 44 33 22 11`.

| 64-bit | 32-bit | 16-bit | 8-bit | Номер |
|--------|--------|--------|-------|-------|
| `rax` | `eax` | `ax` | `al` | 0 |
| `rcx` | `ecx` | `cx` | `cl` | 1 |
| `rdx` | `edx` | `dx` | `dl` | 2 |
| `rbx` | `ebx` | `bx` | `bl` | 3 |
| `rsp` | `esp` | `sp` | `spl` | 4 |
| `rbp` | `ebp` | `bp` | `bpl` | 5 |
| `rsi` | `esi` | `si` | `sil` | 6 |
| `rdi` | `edi` | `di` | `dil` | 7 |
| `r8` | `r8d` | `r8w` | `r8b` | 8 |
| `r9` | `r9d` | `r9w` | `r9b` | 9 |
| `r10` | `r10d` | `r10w` | `r10b` | 10 |
| `r11` | `r11d` | `r11w` | `r11b` | 11 |
| `r12` | `r12d` | `r12w` | `r12b` | 12 |
| `r13` | `r13d` | `r13w` | `r13b` | 13 |
| `r14` | `r14d` | `r14w` | `r14b` | 14 |
| `r15` | `r15d` | `r15w` | `r15b` | 15 |

## Поддерживаемые инструкции

### mov

| Форма | Примеры |
|-------|--------|
| рег, рег | `mov rax, rcx` |
| рег, конст | `mov rax, 42` · `mov rax, 0xB8000` |
| рег, память | `mov rcx, [rdx]` · `mov rax, [rsp+8]` |
| память, рег | `mov [rax], rbx` · `mov [rax + 8], rcx` |
| рег, crN | `mov rax, cr0` · `mov rcx, cr3` |
| crN, рег | `mov cr0, rax` · `mov cr3, rax` |

CR-регистры — управление процессором: `cr0` (защита, пейджинг),
`cr2` (адрес page fault), `cr3` (база таблиц страниц), `cr4` (расширения).

### Арифметика и логика

`add`, `or`, `and`, `sub`, `xor` — только рег,рег и рег,конст:

```text
add rax, rbx   add rcx, 8
or  rax, rbx   or  rcx, 0x100
and rax, rbx   and rax, 0xFF
sub rax, rcx   sub rsp, 32
xor rax, rax   xor rcx, 1
```

### test

```text
test rax, rax   test rcx, 0xFF
```

### Унарные

| Инструкция | Примеры |
|-----------|--------|
| `not` | `not rax` |
| `neg` | `neg rax` |
| `inc` | `inc rax` |
| `dec` | `dec rcx` |

### Сдвиги

| Инструкция | Примеры |
|-----------|--------|
| `shl` | `shl rax, 4` · `shl rax, cl` |
| `shr` | `shr rcx, 8` · `shr rdx, cl` |

Счётчик — константа или `cl` (младший байт `rcx`).

### Стек

```text
push rax   push 0x40   pop rcx
```

`push` принимает регистр или константу; `pop` — только регистр.

### Переходы

`jmp` и условные переходы. Адрес цели — **абсолютное смещение в байтах**
от начала генерируемого кода (не от текущей инструкции):

```text
jmp  0x1000
je   0x2000
jne  0x3000
```

| Инструкция | Условие | | Инструкция | Условие |
|-----------|---------|-|-----------|---------|
| `je` / `jz` | равно | | `jl` | меньше (знак) |
| `jne` / `jnz` | не равно | | `jle` | меньше или равно |
| `jb` | ниже (беззнак) | | `jg` | больше (знак) |
| `jbe` | ниже или равно | | `jge` | больше или равно |
| `ja` | выше (беззнак) | | `js` | отрицательный |
| `jae` | выше или равно | | `jns` | неотрицательный |

### Системные инструкции

| Инструкция | Пример | Описание |
|-----------|--------|---------|
| `cli` | `cli` | Clear Interrupt Flag |
| `sti` | `sti` | Set Interrupt Flag |
| `hlt` | `hlt` | Halt CPU |
| `int` | `int 0x10` | Программное прерывание (константа 0..255) |
| `iret` / `iretq` | `iretq` | Возврат из прерывания (64-bit) |
| `syscall` | `syscall` | Системный вызов |
| `wrmsr` | `wrmsr` | Запись MSR (rcx=номер, edx:eax=значение) |
| `rdmsr` | `rdmsr` | Чтение MSR (rcx=номер → edx:eax) |
| `cpuid` | `cpuid` | CPU Identification (eax=функция) |
| `cqo` / `cqd` | `cqo` | Расширение знака RAX → RDX:RAX |

### Порты ввода-вывода

Поддерживается **только** форма с аккумулятором и константным портом —
как в `asm {}`, так и в `asm32 {}`:

```text
in  al, 0x64     # al <- port 0x64   (asm32: e5 64)
out 0x80, al     # port 0x80 <- al    (asm32: e7 80)
```

Разница между блоками: в `asm {}` к `in`/`out` добавляется REX.W, в
`asm32 {}` — нет (инструкция остаётся 1-байтной). Формы с портом-регистром
(`in al, dx`) не поддерживаются.

### Таблицы дескрипторов

```text
lgdt [rax]       # загрузить GDT из памяти
lidt [rax]       # загрузить IDT из памяти
```

Только форма с памятью.

### Прочее

| Инструкция | Описание |
|-----------|---------|
| `nop` | No Operation |
| `ret` | Возврат из функции |
| `leave` | Восстановить кадр стека |

## AArch64 (`app arm64`)

Блок `asm { }` в `app arm64` кодирует настоящий 64-битный AArch64; регистры —
`x0..x30`, `w0..w30`, `sp`/`wsp`, `xzr`/`zr`, `wzr`. `asm32 { }` — те же
мнемоники с 32-битными (`w*`) регистрами.

```zenith
app arm64

func main() -> int
    asm {
        mov w0, 7              # movz w0, #7
        add w1, w0, 5          # add w1, w0, #5
        lsl x2, x3, 4          # ubfm
        lsr w4, w5, 2
        mul w6, w0, w1         # madd
        ldr x7, [sp, 16]       # [база, смещение кратно 8]
        strb w8, [x0, 4]       # ldrb/strb: слова x*/w*, байты — только w*
        cbz x0, 8              # условя переходы по знаковому смещению в байтах
        b 16
        cset w0, ne
        nop
        br x30                 # bx/ret аналогичны
    }
    return 0
end
```

Поддерживаемые инструкции: `mov` (регистр/конст, любой 64-бит через
movz/movk), `add`/`sub` (2/3-операндные, imm 0..4095, отрицательные — через
обратную операцию), `cmp`, `neg`, `and`/`orr`/`eor`, `mvn`, `lsl`/`lsr`/`asr`
(imm и рег), `mul`/`sdiv`/`udiv`, `ldr`/`str`/`ldrb`/`strb`/`ldrsb`/`ldrsw`
`[база, смещение]` (кратно ширине) и `[база, рег]`, `b`/`bl`/`br`/`blr`/`ret`,
условные суффиксными мнемониками (`beq`/`bne`/`bge`/`blt`/`bhs`/`blo`/`bcs`/`bcc`/...),
`cbz`/`cbnz`, `cset`, хинты `nop`/`wfi`/`wfe`/`sev`/`yield`,
`svc #imm`/`hlt #imm`/`brk #imm`.

### Смещения ветвлений (AArch64)

Число в `b`/`bl`/`b{cond}`/`cbz`/`cbnz` — **знаковое смещение в байтах от
начала самой инструкции** и обязано делиться на 4 (код выравнен по 4).
Ограничения: унарные `b`/`bl` — ±128 МБ, `b.cond`/`cbz`/`cbnz` — ±1 МБ.
`bl <имя функции>` (без числа) вызывает функцию Zenith по имени.

## Thumb / Thumb-2 (`app stm32`)

Блоки `asm { }` / `asm32 { }` в `app stm32` кодируют 32-битный Thumb-2:
низкие регистры `r0..r7` — компактные 16-битные инструкции (ставят флаги),
высокие `r8..r15` — 32-битные Thumb-2. Алиасы `sp`=r13, `lr`=r14, `pc`=r15.

```zenith
app stm32

func main() -> int
    asm {
        mov r0, 5              # movs r0, #5
        add r1, r0, 3          # adds r1, r0, #3
        lsl r2, r2, 4          # imm-сдвиг допустим только при rd==rm
        ldr r3, [r4, 8]        # ldrh/ldrb/str* — см. ниже
        push {r4, r5, lr}
        pop  {r4, r5, pc}
        movw r6, 0x1234        # любой 32-бит: movw/movt, либо mov+.. для r0-r7
        add.w r9, r8, r1       # .w-суффикс принимается и игнорируется
        bx lr
        wfi                    # svc #imm / bkpt #imm / nop / wfe / sev / yield
    }
    return 0
end
```

Поддерживаемые инструкции: `mov` (рег/конст любой 32-бит), `movw`/`movt`,
`add`/`sub` (2/3-операндные, imm ≤ 4095), `cmp` (рег/imm ≤ 4095),
`and`/`orr`/`eor`/`bic`/`mvn`, `mul`, `lsl`/`lsr`/`asr`
(imm-сдвиги ≤ 31 и только при `rd==rm`; иначе регистровый сдвиг),
`ldr`/`str`/`ldrb`/`strb`/`ldrh`/`strh`/`ldrsb`/`ldrsh` `[база, смещение]` и
`ldr`/`str` `[база, рег]` (низкие регистры), `push`/`pop` (только `r0..r7` +
`lr`/`pc`), `b`/`b{cond}` (суффиксы `eq/ne/hs/lo/mi/pl/vs/vc/hi/ls/ge/lt/gt/le`),
`bl <имя функции>` (вызов функции Zenith), `bx`/`blx`, хинты
`nop`/`wfi`/`wfe`/`sev`/`yield`, `svc #imm`, `bkpt #imm`.

### Смещения ветвлений (Thumb)

Число в `b`/`b{cond}` — **знаковое смещение в байтах от начала инструкции**,
обязано быть чётным. Эмиттер кодирует как `(disp - 4) / 2`. Пределы:
`b` — ±2 КБ (imm11), `b.cond` — ±126 байт (imm8). `bl <имя>` через таблицу
фиксапов после генерации тела.

## Валидация ширин

Проверка выполняется для **всех** блоков рекурсивно на этапе генерации кода
(`Codegen::validateAsmWidths`, перед эмиссией). Правила:

- `asm { }` (`wordSize = 0`) — нативная ширина таргета, допустима везде;
- `asm32 { }` — x86-64, x86-32, arm64, stm32; **запрещена** при
  `asm_word_size: 16`;
- `asm16 { }` — только для real-mode x86-образов (`asm_word_size: 16`);
- любой asm-блок в `app wasm` — ошибка при разборе.

Нарушение — `Codegen error` с текстом разрешённого набора (см. матрицу выше).
Эмиттеры неподдерживаемых инструкций или операндов выдают warning и
пропускают строку.

## Примеры

### Переход в 64-bit Long Mode (фрагмент)

```zenith
app efi

func main() -> int
    cli()

    asm {
        lgdt [rax]           # загрузить GDT
        mov rax, cr4
        or rax, 0x20         # PAE bit
        mov cr4, rax
        mov rax, cr0
        or rax, 0x80000000   # PG bit
        mov cr0, rax
    }
    return 0
end
```

### Чтение CPUID

```zenith
app efi

func main() -> int
    asm {
        mov rax, 1
        cpuid
        # rbx, rcx, rdx = информация о CPU
    }
    return 0
end
```

## Ограничения

- `asm {}`/`asm32 {}` — x86 (для x86-таргетов) и AArch64/Thumb-2 (для arm64/stm32);
  `asm16 {}` — только 16-битный real-mode x86.
- Нет меток и символов (кроме `bl <имя функции>` и `call` для x86-таблиц) —
  для переходов только числовые смещения. Семантика зависит от таргета:
  - **x86** (`asm`/`asm32`/`asm16`): `jmp`/`jcc` — абсолютное смещение в
    байтах от начала генерируемого кода (не от текущей инструкции);
  - **AArch64** и **Thumb**: смещение в байтах от начала самой инструкции
    (обязано делиться на 4 / быть чётным соответственно).
- В `asm {}` имена x86-регистров 8/16/32-бит (`al`, `ax`, `eax` и т.д.)
  принимаются, но трактуются как 64-битные (с REX.W).
  В `asm32 {}` размер описанных операндов фиксируется 32-битным.
- `#` нельзя использовать перед операндами (`#5`, `[r3, #4]`) — это комментарий
  Zenith; пишите `5`, `[r3, 4]`.
- Память — только `[база+смещение]`, без масштабирования.
- В Thumb imm-сдвиги (`lsl r2, r2, 4`) требуют `rd == rm`; `push`/`pop` — только
  `r0..r7` + `lr`/`pc`.
- `in`/`out` — только `аккумулятор, константный порт`; формы с `dx` не
  поддерживаются.
- `lgdt`/`lidt` — только форма с памятью.
- Нет поддержки XMM/SSE/AVX (x86) и FPU/SIMD в asm-блоках.
- Неподдерживаемая инструкция или комбинация операндов: warning и пропуск.
