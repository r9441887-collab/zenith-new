# ARM64 режим (AArch64, app arm64)

Zenith умеет компилировать прошивки для 64-битных ARM-процессоров
(архитектура AArch64, начиная с Cortex-A53). Выход — плоский
позиционно-независимый бинарный образ `.bin`, который запускается в QEMU
(машина `virt`) или загружается как голое ядро. Компилятор сам кодирует
все AArch64-инструкции (MOVZ/MOVK, LDUR/STUR, ADDS/SUBS, BL и т.д.) —
никаких внешних тулчейнов и libc не требуется.

## Тип приложения

```zenith
app arm64
    chip: cortex-a53     # необязательно (информационно, для QEMU)
    clock_hz: 62500000   # необязательно (частота CPU в Гц, калибрует delay_ms)
```

| Директива | Значение | По умолчанию |
|-----------|----------|--------------|
| `chip:` | Название чипа (напр. `cortex-a53`) | `cortex-a53` |
| `clock_hz:` | Тактовая частота CPU в Гц, используется для калибровки `delay_ms()` | `62500000` |

Архитектура для `app arm64` — ARM64 (AArch64) автоматически; флаги
`--32bit`/`--64bit`/`--arm` с ним несовместимы (ошибка компиляции).

## Сборка и запуск

```bash
zenith fw.z                # arm64 -> fw.bin
qemu-system-aarch64 -machine virt -cpu cortex-a53 -kernel fw.bin -nographic
```

- Точка входа — `func main()` (либо первая функция, если `main` нет).
- Образ: `[старт] [рантайм-помощники] [функции пользователя] [данные]`.
- Глобальные переменные и строки — в секции данных; регистр `x19` всегда
  указывает на её начало (глобалы адресуются как `x19 + смещение`).

## Вывод текста (print)

`print()` передаёт текст/числа в отладочный вывод через UART PL011
по адресу `0x09000000` (стандартный последовательный порт машины QEMU
`virt`). Поддерживаются строки, целые числа (со знаком, 32-бит) и символы;
печать чисел не добавляет перевода строки.

## Встроенные функции

| Функция | Описание |
|---------|----------|
| `print(x)` | Вывести строку / целое / символ в PL011 UART |
| `delay_ms(ms)` | Задержка (цикл ожидания, калибруется по `clock_hz:`) |
| `abs(x)` | Модуль числа |
| `min(a, b)` / `max(a, b)` | Минимум / максимум |
| `clamp(x, lo, hi)` | Ограничить `x` диапазоном `[lo; hi]` |
| `str_len("text")` | Длина строки в байтах |

`gpio_*` и `led_*` на этом таргете не имеют эффекта (компилятор выдаёт
предупреждение) — GPIO-контроллер машины `virt` не задействован.

## Модель данных

- Все целые значения — 32-битные знаковые; загрузки используют `LDRSW`
  (знаковое расширение в 64-битные регистры), поэтому деление/остаток со
  знаком корректны.
- Структуры: каждое поле по 4 байта (32-битная модель, как в остальных
  таргетах Zenith).
- Массивы, глобальные переменные и вложенные циклы/ветвления — поддерживаются.
- Вещественных чисел (float) на этом таргете нет.
- Аргументы функций — в регистрах `x0..x7` (до 8), результат в `x0`;
  локальные переменные живут в кадре вызываемого ([SP + смещение]);
  `x29/x30` — frame pointer / link register; SP выровнен по 16 байт.

## Пример

```zenith
app arm64
    chip: cortex-a53
    clock_hz: 62500000

func add(a: int, b: int) -> int
    return a + b
end

func main()
    print("Hello, ARM64!")
    print(add(2, 3))
    var i: int = 0
    while i < 3
        print(i)
        i = i + 1
    end
    print("done")
end
```

Проверено в QEMU: `qemu-system-aarch64 -machine virt -cpu cortex-a53
-kernel fw.bin -nographic` (вывод `print()` корректно появляется в
терминале, исключений нет).
